# Discovery and read markers

Apply migrations 000006 and 000007 before starting the updated API (`make start` applies pending migrations). Production migrations should follow the normal deployment process.

- `GET /users?q=al`: bearer authentication required; at least two Unicode characters, at most 64 UTF-8 bytes. Returns up to 20 `{id, username, display_name}` objects, excluding the caller. Matches username or display-name prefixes, case-insensitively. Display names are backfilled from usernames and fall back to the username when empty. The previous `search=` parameter remains supported for frontend compatibility; `q` takes precedence.
- `GET /rooms/public?q=team&limit=20&offset=0`: no authentication required; returns only public group rooms. `q` is an optional literal, case-insensitive name substring (maximum 100 bytes). Default limit is 50, maximum 100; offset defaults to zero. Results are an array ordered by `(created_at, id)`. Empty results are `[]`.
- `POST /rooms`: accepts the existing `{name}` plus optional `is_public` (default false). Existing rooms remain private, and the database prevents public DMs. Visibility controls discovery; existing group join/leave semantics are unchanged.
- `POST /rooms/{id}/read`: bearer authentication and current membership required. Body: `{"message_id":"uuid"}`. The message must exist in that room. Returns 204 after saving and publishing. Per-member updates serialize across tabs/devices and advance only by `(created_at, id)`, never backwards.
- `GET /rooms`: adds `is_public`, `unread_count`, and `last_message`. Counts include other users' messages after the caller's read marker; without a marker all existing messages from other users count, including history before joining. Last message is `null` for an empty room, otherwise `{id, sender_id, type, body, created_at}` with body limited to 280 characters. Media previews have their message type and may have an empty body.

Successful read calls publish `{"type":"read","room_id":"uuid","user_id":"uuid","message_id":"uuid"}` to current room members, including the reader's other tabs. The message ID is the effective persisted marker, which may be newer than a stale request. Events use the existing Hub/Redis Pub/Sub transport. Repeated calls can emit duplicate events; read receipts are not a durable event stream. If publication fails after persistence, the endpoint returns 503; retrying safely republishes the effective marker. Concurrent receipts can arrive out of order; clients should not regress their displayed read position.

Deleting a referenced message clears its read marker through the foreign key. Integration tests use an isolated schema when `PULSECHAT_TEST_DATABASE_URL` is set; CI supplies a disposable PostgreSQL service. They verify migration up/down, public filtering, user limits, unread counts, equal timestamp ordering, concurrent updates, and marker deletion.
